### 2.4 实时协作技术

【说明】2.4 已由用户本人手稿定稿（OT 对比整段删除由 1.2 承担；收尾句连接 CRDT 理论与 Yjs 实现；已修正"中央处理器"→"中央服务器"两处、"实现……时"语法磕绊）：

> CRDT算法。CRDT是一种能让多个设备在离线或弱网环境下独立修改数据，联网后自动合并、最终达到一致的数据结构方案。它最大的优点是不需要中央服务器协调，各副本自行操作，同步时靠数学性质自动解决冲突，为本系统的多人编辑提供了技术支持。

### 2.6 大语言模型与检索增强相关技术（新增节）

【说明】AI 起草候选（用户风格、点到为止，每小节一个定义句加一个落点），粘贴前可自行修改；四小节分别为 4.2.7 网关与权限收敛设计、5.10.1/5.10.2 流式实现、5.10.4 混合检索埋伏笔：

> 大语言模型与OpenAI兼容接口。大语言模型是在海量文本上训练而成的生成式模型，能够理解自然语言指令并生成结构化的文本内容，DeepSeek 和 GPT 都属于这一类模型。主流厂商的接口在请求和响应格式上普遍互相兼容，因此应用只需要对接一次，就可以在不同模型之间自由切换，本系统的AI网关正是利用这一特性实现模型可插拔的。
>
> 服务器推送事件。大模型生成内容是逐字产出的，如果等全部生成完再返回，用户就要面对长时间的空白等待。服务器推送事件（SSE）基于HTTP建立一条单向长连接，让服务器把生成的内容一段一段推送给浏览器，从而实现边生成边显示的效果。
>
> 文本向量化与语义检索。传统的关键词检索只能匹配字面，无法命中意思相近但用词不同的内容。文本向量化由嵌入模型把文字转换成一串数字组成的向量，语义相近的文本在空间中的距离也相近，因此可以按含义进行检索，本系统借助pgvector扩展在数据库中完成向量的存储与相似度计算。
>
> 函数调用与智能体。函数调用让模型能够以结构化的方式请求使用某个工具，系统执行工具后再把结果返回给模型，模型据此继续生成，如此循环直到完成任务，这样的应用通常被称为智能体。智能体具备写操作能力后，它的每次工具调用都必须置于系统自身的权限控制之下，这也是本系统设计的关键出发点。

### 4.4 实时协作设计（整节改写，2026-10-18 候选）

【说明】AI 起草、用户风格：四个小节保持定稿结构，第 4 小节补 AI 协作者衔接；图 4-7（数据流）已重绘为双轨数据流图（docs/v2/assets/4-7-实时同步数据流图.png），图 4-8 已用生产库真实数据重绘（黑底终端风格，与 4.3 图表一致），新增图 4-9 AI 写入协作链路图。

> 1、WebSocket连接管理。浏览器在WebSocket握手时无法自定义请求头，所以JWT通过查询参数传递，服务端在升级握手的阶段校验令牌和笔记的访问权限，校验失败直接返回401；连接建立后由y-websocket负责保活、广播和断连清理，最后一个连接断开时执行会话收尾。协作通道与REST接口共用同一个进程，经Nginx按同一套规则反向代理。

### 5.2 用户认证模块实现

#### 5.2.1 注册功能实现

> 注册界面如图5-2所示，用户需要输入邮箱/用户名/密码信息，密码要求至少8位且同时包含字母和数字。注册成功后自动登录并进入工作台，已有账号的用户可以点击"直接登录"。
>
> 表单校验由前端和后端共同完成。前端基于Ant Design的表单组件配置规则，例如密码字段要求8到32位且同时包含字母和数字：
>
> ```tsx
> { required: true, min: 8, max: 32, message: '密码 8-32 位' },
> { pattern: /^(?=.*[A-Za-z])(?=.*\d).+$/, message: '必须同时包含字母和数字' },
> ```
>
> 确认密码字段依赖密码字段做一致性校验。后端用class-validator再做一遍校验，规则以装饰器的形式写在注册参数对象上：
>
> ```ts
> export class RegisterDto {
>   @IsEmail({}, { message: '邮箱格式不正确' })
>   email: string;
>
>   @IsString()
>   @MinLength(3, { message: '用户名至少 3 个字符' })
>   @MaxLength(50)
>   @Matches(/^[\w一-龥-]+$/, { message: '用户名只能包含字母、数字、下划线、中文和连字符' })
>   username: string;
>
>   @IsString()
>   @MinLength(8, { message: '密码至少 8 位' })
>   @MaxLength(32)
>   @Matches(/^(?=.*[A-Za-z])(?=.*\d).+$/, { message: '密码必须同时包含字母和数字' })
>   password: string;
> }
> ```
>
> 校验通过后进入服务层，先查邮箱与用户名的唯一性，冲突时返回409，再对密码做哈希后入库，返回给前端的用户信息不包含密码字段：
>
> ```ts
> async register(dto: RegisterDto) {
>   if (await this.usersService.existsByEmail(dto.email)) {
>     throw new ConflictException('该邮箱已被注册');
>   }
>   if (await this.usersService.existsByUsername(dto.username)) {
>     throw new ConflictException('该用户名已被占用');
>   }
>   const password_hash = await bcrypt.hash(dto.password, 10);
>   const user = await this.usersService.create({
>     email: dto.email,
>     username: dto.username,
>     password_hash,
>   });
>   return user.toSafe();
> }
> ```

#### 5.2.2 登录与JWT Token生成

> 登录界面如图5-3所示，用户需要输入邮箱和密码，密码框支持显示与隐藏切换。登录成功后进入工作台，还没有账号的用户可以点击"立即注册"跳转到注册页。
>
> 服务端收到登录请求后，先按邮箱查询用户，再用bcrypt比对密码哈希。这里有一个细节：邮箱不存在和密码错误返回的是同一句提示"邮箱或密码错误"，避免通过提示语判断某个邮箱是否已经注册。校验通过后签发HS256的JWT，载荷中包含用户标识、用户名、令牌编号和过期时间，令牌编号的作用是支持登出时把令牌加入黑名单，实现登出即失效。返回给前端的是令牌和脱敏后的用户信息，前端把它保存在本地，后续请求通过Authorization请求头携带。
>
> 核心代码：LoginPage.tsx（表单规则与登录提交）、auth.service.ts（凭据校验与JWT签发）、auth.controller.ts（登录与登出接口）。

#### 5.2.3 路由守卫与身份校验

> 登录成功后进入工作台，如图5-4所示。工作台左侧是搜索框、AI智能搜索入口、文件夹、标签、团队和回收站，中间是笔记列表，右侧是编辑区；未登录用户直接访问受保护页面时会被拦截并跳转到登录页。
>
> 后端在全局注册了JwtAuthGuard，每个请求先解析Authorization请求头中的Bearer令牌，再查一次Redis中的登出黑名单，命中黑名单的令牌直接拒绝，这样登出之后旧令牌立刻失效，不需要等到过期。前端用React Context维护登录状态，启动时读取本地保存的令牌并请求一次用户信息来恢复会话，任何接口返回401时清除本地令牌并统一跳转到登录页。
>
> 核心代码：JwtAuthGuard（全局守卫与令牌校验）、jwt.strategy.ts（令牌解析与用户注入）、AuthContext.tsx（登录态维护与401跳转）。

### 5.10 AI智能辅助模块实现

#### 5.10.1 LLM网关实现

> 网关实现为NestJS中的独立模块，向全系统提供对话、流式对话和向量化的统一接口。系统默认接入DeepSeek的API，流式回复通过SSE逐帧下发；模型返回的思维链内容由网关剥离，不进入正文，工具调用的流式分片由网关聚合成完整调用后再交给智能体执行。上游限流时按指数退避重试，密钥配置错误则直接透出上游状态。每一次调用都会把模型、令牌消耗和耗时写入消息表，用量做到可查。由于DeepSeek的接口不提供向量化端点，向量通道单独配置为任意兼容的服务，本系统采用百炼的文本嵌入模型，未配置时智能检索功能自动隐藏，其他功能不受影响。实测一次续写调用全链路返回187个事件帧、生成正文348字，用量记录中的总令牌为774，其中思维链令牌483个已全部剥离；向量接口批量嵌入3条文本耗时287毫秒，返回1024维向量。

#### 5.10.2 编辑器AI与协同编辑的集成

> 编辑器工具栏提供智能菜单，展开润色、摘要、翻译、续写和自定义指令五类动作（如图5-25所示）。前端把动作和选区上下文提交给智能接口后进入等待状态，编辑器本地锁定为只读，工具栏实时显示已生成的字数并提供停止按钮；文本流在浏览器端缓冲，生成完成或者用户中断之后，把整块Markdown一次性解析插入文档。
>
> 采用整块插入而不是逐字写入，是因为实测暴露了两个问题：一是思考型模型的思维链也计入输出预算，逐字写入时正文在预算耗尽后仍然是零输出，后来把输出上限提高到8192才解决；二是逐字插入纯文本会打碎Markdown结构，表格的分隔符变成裸文本，代码块被段落拆分，光标位置还会随内容漂移并在中途抛错。整块插入让多段、列表、行内代码和代码块的结构都由解析器保证正确，单一事务也让协作端整段原子可见（如图5-26所示，对端与发起端的内容逐字一致），并且可以整体撤销。

#### 5.10.3 智能体工具调用与权限收敛

> 智能体以编辑器侧边抽屉的形式呈现（如图5-27所示），服务端实现规划、工具调用、结果回填、继续生成的循环，单轮工具步数上限为6步，防止循环失控。工具注册表初始收录五类非破坏性工具，包括笔记检索、笔记读取、笔记创建、笔记更新和分享链接生成，全部直接复用既有的业务服务，刻意不收录删除、回收站和链接停用这类破坏性操作，更新类操作的误写风险由版本快照兜底。
>
> 权限收敛是本模块的核心：工具执行前先以对话用户的身份通过访问矩阵校验，例如非管理员用户指令智能体为团队笔记创建编辑权限的永久链接时，工具返回权限不足，原因回填对话，模型在回答中如实告知用户，而不是静默失败。实测多步指令"检索包含关键字的笔记并为第一篇创建七天只读分享链接"，智能体依次完成检索和创建两步工具调用，在回答中给出了链接路径；新建笔记的内容经校验，标题、加粗列表和代码块的结构都正确。全部工具调用的时间、工具、参数和结果都可以在审计接口按时间倒序查询。

#### 5.10.4 智能整理与混合检索

> 智能整理采用显式触发的设计：单篇笔记通过AI整理弹窗生成或刷新摘要卡和标签建议，勾选后一键采纳（如图5-28所示）；存量笔记的批量整理在进程内顺序执行，每轮上限20篇并轮询进度，实测5篇9秒完成。整理结果写入独立的元数据表，与笔记主表解耦，生成失败不会污染正文。
>
> 混合检索的向量化在重索引任务中完成，对用户可见范围内有正文的笔记做滑窗切片，实测6篇笔记生成10个1024维的向量切片。查询时关键词和语义两路召回经RRF融合，界面用标签区分命中通道并展示融合得分和命中的原文片段（如图5-29所示）；语义通道支持零字面重叠的查询，以"怎么防止容器把宿主机资源吃光"检索，能够命中字面完全不同但语义相关的"资源限制"笔记，同类文本与无关文本的余弦相似度实测分别为0.528和0.195，区分度充分。检索SQL的可见范围判定与访问矩阵严格同口径，实现过程中曾暴露团队笔记只判断可见性而没有校验成员资格的越权泄漏，经端到端测试发现后补齐三处成员资格谓词修复，这个过程也印证了智能检索权限对齐的必要性。检索结果可以作为上下文发起带出处的问答，回答用编号标注引用片段，依据不足时如实说明。

### 7.2 系统创新点

【整节替换为】

> 1、智能体纳入多用户权限模型的收敛设计。系统将智能体定位为与个人用户、团队成员、访客并列的第四类操作主体，但智能体不拥有独立身份：每次工具调用以对话用户身份执行，先通过与 REST 及 WebSocket 一致的访问矩阵校验，拒绝原因回填供模型自我修正，初始工具集遵循最小破坏面原则并以版本快照兜底，调用全程可审计。开源同类实现中，具备智能体能力者多为单用户系统或独立于笔记系统的对话平台，本方案使权限模型保持单一事实来源，属自主设计。
> 2、模型可插拔的智能网关与全链路私有化。网关统一实现 OpenAI 兼容协议，一个配置项即可切换模型服务商乃至指向本地部署的模型；对话与向量化双通道解耦，向量能力缺失时仅检索功能降级。结合四容器私有部署，笔记数据与智能调用可全链路不出内网。相比之下，商业产品的智能能力普遍与自家云服务和模型绑定，其私有化部署面向大型企业客户且门槛高企——以腾讯文档企业版私有化版为例，许可证需 500 人起购——个人用户与中小团队难以企及；开源同类方案的智能能力亦多与云订阅耦合。本方案以单机四容器的部署成本即可获得完整的数据主权与可审计的智能链路，在私有化门槛与模型解耦两方面形成差异化。
> 3、CRDT 落地的自主工程方案与智能输出的协同链路融合。持久化层面，系统在 Yjs 同步原语之上自主实现了增量回放与快照播种、缓冲合并入库、会话收尾合并回写与压缩、防误清保护及冷热双路径版本回滚；智能集成层面，编辑器智能输出经缓冲与整块解析以单一事务写入 Yjs 文档，与人工键入完全同路，多端一致性由 CRDT 算法保证而无需额外的同步逻辑。每个环节均有核心代码、设计依据与测试用例支撑。
