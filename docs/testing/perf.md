## 6.3.1 接口响应时间

采样：登录 20 次（含 bcrypt 校验成本），其余各 50 次，经 nginx 反代、局域网访问。

| 接口 | n | avg (ms) | p95 (ms) | max (ms) |
|---|---|---|---|---|
| POST /auth/login（含 bcrypt） | 20 | 72.8 | 77.5 | 77.5 |
| GET /notes（列表） | 50 | 5.3 | 7.2 | 8.8 |
| GET /notes/:id（详情含 JSONB 正文） | 50 | 5.6 | 8.2 | 8.5 |
| GET /notes?keyword=（全文搜索） | 50 | 5.3 | 7.7 | 9.4 |
| 写入（POST 创建 + DELETE 软删，两次往返） | 50 | 23.8 | 28.5 | 43.8 |

解读：读接口 avg≈5.3ms（含 nginx 反代 + JWT 校验 + PostgreSQL 查询 + 局域网往返）；
登录 72.8ms 主要是 bcrypt 10 轮哈希的刻意计算成本（论文 3.4.2 安全性设计），属预期；
写入 23.8ms 为创建+软删两次请求合计（单请求约 12ms），软删除含 recycle_bin 插入。

## 6.3.2 WebSocket 并发连接

方案：200 个客户端分 4 批连入 2 篇笔记（模拟多人陆续进入协作），经 nginx 反代。

| 指标 | 数值 |
|---|---|
| 建连成功率 | 200/200（100%） |
| 建连耗时 avg / p50 / p95 / max | 10.0 / 9.3 / 13.4 / 29.1 ms |
| 全部发起+收敛总耗时 | 13.8 s（含脚本 25ms/连接的节奏控制与 5s 保持） |

解读：y-websocket 每连接一个内存 Y.Doc 共享 + ping 保活，200 并发下建连 p95 仅 13.4ms；
瓶颈在脚本节奏而非服务端。按 NAS 4 核与每连接内存占用估算，千级连接可行（论文 7.3 可展望）。

## 6.3.3 实时编辑延迟

方案：A/B 两客户端同连一篇笔记，A 插入字符（后即删除，净变化为零），以 B 的 Yjs update
事件到达时刻计算"A 提交 → 服务器广播 → B 收到"的单向传播延迟，采样 30 次。

| 指标 | 数值 |
|---|---|
| n | 30 |
| avg / p50 / p95 / max | 0.8 / 0.8 / 1.7 / 3.1 ms |

解读：延迟构成 = A 发送 + 服务端 y-protocols 广播 + B 接收（局域网 RTT ≈1ms 内）。
亚毫秒级均值表明 CRDT 广播路径无持久化阻塞（增量入库走 2s 缓冲异步，不挡传播）——
这正是 D-007"增量日志与实时传播分离"设计的直接收益（论文 4.4.2 可引用）。

## 6.3.4 测试结果分析（论文 6.3.4 素材）

1. **读接口稳定在个位数毫秒**：列表/详情/搜索 avg 均 ≈5.3ms 且 p95 <8.5ms，说明
   NestJS 管道 + TypeORM 查询 + nginx 反代的常规链路开销可控；搜索与列表同量级，
   ILIKE 子串匹配在当前数据量（数十条）下不构成瓶颈（7.3 已列 zhparser/pg_trgm 演进）。
2. **写接口约为读的 4 倍**：23.8ms 中包含两次完整往返与 recycle_bin 写入，仍远低于
   常见 100ms 的交互舒适阈值；bcrypt（登录 72.8ms）是唯一"慢"接口，且属安全设计的预期成本。
3. **协作链路显著快于 REST 链路**：编辑传播 avg 0.8ms vs REST 读 5.3ms，因为 Yjs 增量
   走内存广播（持久化异步化），验证了 4.4.2 同步机制的架构收益。
4. **并发能力满足论文场景**：200 并发协作连接 100% 成功、建连 p95 13.4ms；毕业设计
   演示规模（个位数同时在线）下余量充足。
5. **测试口径说明**：客户端与服务端同处局域网，数据不含公网 RTT；所有脚本可复现
   （scripts/perf/），重跑数值会有毫秒级浮动。
