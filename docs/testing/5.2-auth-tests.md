# 5.2 用户认证模块 功能测试用例表（论文 6.2.1 素材）

> 测试日期：2026-09-08　环境：macOS（node 22.22）+ NestJS :13000 + NAS PostgreSQL :15432 + Redis :16379
> 方法：curl 直打 API + headless Edge 界面截图；数据均为真实运行结果。

| 编号 | 用例 | 前置条件 | 操作步骤 | 预期结果 | 实际结果 | 结论 |
|---|---|---|---|---|---|---|
| AUTH-01 | 合法注册 | 库中无该邮箱/用户名 | POST /auth/register（email=demo@wangyan.test, username=演示用户, 密码含字母数字≥8位） | 201，返回脱敏用户对象 | 201，返回 id/email/username/avatar_url，users 表新增一行，密码为 bcrypt 哈希（$2a$10$…） | ✅ |
| AUTH-02 | 用户名过短 | —— | POST /auth/register（username=凌天，2 个字符） | 400，提示"用户名至少 3 个字符" | 400，message 数组含该文案 | ✅ |
| AUTH-03 | 弱密码拦截 | —— | POST /auth/register（password=short） | 400，提示长度与复杂度错误 | 400，返回两条校验文案 | ✅ |
| AUTH-04 | 重复邮箱 | AUTH-01 已注册 | 同邮箱再次注册 | 409 该邮箱已被注册 | 409，文案一致 | ✅ |
| AUTH-05 | 重复用户名 | AUTH-01 已注册 | 换邮箱、同 username 注册 | 409 该用户名已被占用 | 409，文案一致 | ✅ |
| AUTH-06 | 错误密码登录 | AUTH-01 账号存在 | POST /auth/login（密码错误） | 401 | 401，"邮箱或密码错误" | ✅ |
| AUTH-07 | 正确登录 | AUTH-01 账号存在 | POST /auth/login（正确密码） | 200，返回 access_token 与用户信息 | 200，JWT 含 sub/username/jti/exp | ✅ |
| AUTH-08 | 守卫拦截无 token | —— | GET /users/me（不带 Authorization） | 401 | 401 | ✅ |
| AUTH-09 | 带 token 访问 | 持 AUTH-07 的 token | GET /users/me（Bearer Token） | 200，返回当前用户 | 200，与登录用户一致 | ✅ |
| AUTH-10 | 登出后 token 失效 | 持有效 token | POST /auth/logout 后立即用原 token 访问 /users/me | 登出 200；再访问 401 | 200 → 401"登录状态已失效"；Redis 出现 auth:denylist:{jti} 键 | ✅ |
